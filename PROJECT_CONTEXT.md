# Контекст проекта Market News

Рабочая карта проекта для последующих правок. Секреты и содержимое `.env` сюда не
записываются.

Дата первичного аудита: **4 ноября 2026 года**.

## Назначение

Telegram-бот на `aiogram` для деловых и рыночных новостей:

- получает англоязычные материалы через GNews;
- сохраняет их в PostgreSQL;
- показывает дайджест, последние новости, категории и аналитику;
- переводит материалы на русский и арабский через CVC/OpenAI-compatible API;
- отправляет дневной дайджест всем пользователям с включённой рассылкой;
- отправляет новые материалы пользователям Plus/Pro по выбранным источникам;
- принимает оплату Telegram Stars;
- содержит статичный лендинг в `landing/index.html`.

## Структура

| Файл | Ответственность |
|---|---|
| `main.py` | Telegram router, команды, callback-и, FSM админки/поиска, платежи, scheduler, graceful shutdown |
| `config.py` | конфигурация из `.env`, лимиты, языки, расписания, тарифы |
| `db.py` | PostgreSQL schema, миграции, CRUD пользователей/источников/статей/переводов/платежей |
| `models.py` | dataclass-модели `Article`, `Source`, `User` |
| `gnews.py` | запросы GNews, нормализация входных статей, разбор дат и источников |
| `content.py` | очистка текста/URL, классификация тем, рендер HTML, гейт внешних ссылок |
| `texts.py` | интерфейсные строки RU/EN/AR и команды бота |
| `keyboards.py` | inline-клавиатуры и callback data |
| `screens.py` | сборка экранов из БД, рендера и клавиатур |
| `jobs.py` | опрос GNews, перевод/фото-worker, пуши и дневные дайджесты |
| `translate.py` | перевод батчей, нормализация JSON-ответа и тем |
| `images.py` | загрузка/конвертация картинок и кэширование Telegram `file_id` |
| `ui.py` | отправка и редактирование Rich Message с fallback без изображений |
| `landing/index.html` | статичный русско-англо-арабский лендинг |
| `tests/` | unit-тесты контента, клавиатур, GNews, платежных/сервисных сценариев и shutdown |

## Поток данных

1. `main.run()` подключает PostgreSQL, настраивает Telegram и запускает scheduler.
2. При старте выполняется `refresh_catalog()`:
   - `poll_gnews(..., "top")`;
   - `poll_gnews(..., "search")`.
3. Scheduler повторяет search, top и проверку дайджестов.
4. `translation_worker()`:
   - пытается отправить новые пуши;
   - переводит отсутствующие RU/AR-версии;
   - повторно пытается отправить ожидающие пуши.
5. Отдельный быстрый `image_worker()` параллельно загружает изображения в
   Telegram и сохраняет `file_id`, не блокируя перевод и рассылку.
6. Пользовательские экраны используют только данные из `screens.py` и `db.py`;
   Telegram-вызовы сосредоточены в `main.py` и `ui.py`.

## Важные инварианты

- Новость на пользовательском языке показывается только если перевод сохранён и
  его `source_hash` совпадает с исходной статьёй.
- Первые внешние ссылки защищены `content.links_allowed()`:
  нужны минимум `LINKS_AFTER_STEPS` действий и `LINKS_AFTER_OPENS` открытых
  новостей. Запрещённые хосты и сокращатели фильтруются.
- Бесплатная версия получает дневной дайджест; источники и лимиты определяются
  через `source_limit_for()` и таблицу `user_sources`.
- При включении источника уже существующие статьи помечаются в
  `article_pushes`, чтобы они не ушли как «новые» пуши.
- Все callback-и должны укладываться в лимит Telegram callback data (64 байта);
  это проверяется тестами.
- Тексты интерфейса должны иметь одинаковый набор ключей в `ru`, `en`, `ar`.
- Доступ к БД — только через `Database`; пользовательские данные не следует
  добавлять в глобальное состояние процесса.

## Тарифы и фактическая текущая логика

Настройки по умолчанию находятся в `.env.example`:

- Base: до 5 источников, дневной дайджест;
- Plus: 200 Stars / 30 дней, до 100 источников;
- Pro: 500 Stars / 30 дней, до 500 источников.

Пуши отправляются только активным Plus/Pro, если статья принадлежит включённому
источнику, ещё не отправлялась и (для RU/AR при включённом CVC) уже переведена.

## Что учитывать при следующих правках

1. `TZ_PRAVKI.MD` — спецификация изменений, а не гарантия полной реализации.
   Особенно отдельно проверить:
   - добавление собственных RSS/сайтов пользователем;
   - различие частоты опроса Pro и остальных тарифов;
   - точное количество реально рабочих лент в интерфейсе и лендинге;
   - соответствие всех новых экранов RU/EN/AR.
2. Сейчас поиск источника в «Моей ленте» ищет только источники, которые уже
   есть в каталоге (`source_search_prompt` и `search_sources`).
3. GNews собирается на английском (`GNEWS_LANGS = ("en",)`), локализация идёт
   отдельным worker-ом. При пустом `CVC_API_KEY` RU/AR-экраны могут не иметь
   готовых материалов.
4. Search чередует три тематических запроса, фильтрует статьи до сохранения и
   опрашивается раз в минуту с 07:00 до 22:00 по `GNEWS_SEARCH_TIMEZONE`,
   ночью — раз в 30 минут. Отдельной фактической частоты для Pro сейчас нет.
5. `render_sources(..., allow_link=...)` принимает флаг, но текущий экран
   источников внешние ссылки не добавляет. Меняя это, не обходить гейт ссылок.
6. `SERVER.md` содержит старые эксплуатационные заметки; README и
   `docker-compose.yml` описывают актуальную PostgreSQL/Docker-схему.
7. `gnews_search_sample.json` — локальный пример ответа, не источник runtime-
   данных; в текущем sample-ответе статей нет.

## Проверки перед изменениями

Из корня проекта:

```powershell
.venv\Scripts\python.exe -m unittest discover -s tests -v
.venv\Scripts\python.exe -m compileall -q config.py content.py db.py gnews.py images.py jobs.py keyboards.py main.py models.py screens.py texts.py translate.py ui.py tests
git diff --check
git status --short
```

Интеграционные тесты PostgreSQL запускаются только при заданном
`TEST_DATABASE_URL`.

## Правила работы с окружением

- Не читать и не выводить значения `.env`.
- Не коммитить `data/`, `.venv/`, `*.sqlite3`, `gnews_search_sample.json`.
- Для локального запуска без Docker нужен PostgreSQL и корректный
  `DATABASE_URL`.
- Для контейнеров использовать `docker compose up --build -d`; сервис
  PostgreSQL опубликован на `127.0.0.1:5433`, лендинг — на `:8080`.
